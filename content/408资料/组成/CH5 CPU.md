### 微程序控制器的基本概念
微程序设计思想：<span style="color:rgb(255, 0, 0)">每条机器指令</span>编写成一个<span style="color:rgb(255, 0, 0)">微程序</span>，<span style="color:rgb(255, 0, 0)">每个微程序包含若干微指令</span>，每个<span style="color:rgb(255, 0, 0)">微指令对应一个或几个微操作命令</span>。这些微程序可以存到一个<span style="color:rgb(255, 0, 0)">控制存储器</span>CM/CS中，用寻址用户程序机器指令的方式来寻址每个微程序中的微指令。目前，大多数计算机都采用微程序设计技术。
控存由<span style="color:rgb(255, 0, 0)">ROM芯片</span>组成，存取方式-<span style="color:rgb(255, 0, 0)">按地址访问-随机存取</span>

区分主存和控制存储器：主存用于存放程序和数据，主存由ROM和RAM实现；
控制存储器用于存放微程序，在CPU内部，用ROM实现。

<span style="color:rgb(255, 0, 0)">微命令</span>就是<span style="color:rgb(255, 0, 0)">控制信号</span>
指令寄存器IR里面放的是机器指令；一条机器指令对应一段微程序；
对应关系：

| 1条机器指令   | 1个（段）微程序 |
| -------- | -------- |
| 1个（段）微程序 | 多个微指令    |
| 1个微指令    | 多个微命令    |
| 1套微命令    | 1个微操作    |
例如，(PC)->MAR是微操作；微命令是PCout=1,MARin=1;

微程序控制器基本结构
1.微地址形成部件：根据机器指令op生成微程序入口地址，并根据当前微指令顺序控制字段及状态条件，生成后续微地址。
2.uPC：接收微地址形成部件提供的微地址，作为控存的读地址；
3.控制存储器CS/CM：ROM组成，随机存取，存放微指令。
4.微指令寄存器uIR：暂存从控存中读出的微指令，并将操作控制字段和顺序控制字段分别送至执行单元和微地址形成部件。
### 增量法（有uPC）
1.执行<span style="color:rgb(255, 0, 0)">取指令公共操作</span>。系统启动或每条指令执行完毕后，将取指微程序的入口地址（通常为CM的0号）送入uPC。随后从CM中读首条取指微指令并送入uIR；
完成取指微程序后，从主存中取出的机器指令被存入指令寄存器IR。
2.生成<span style="color:rgb(255, 0, 0)">当前指令的微程序入口地址</span>：根据<span style="color:rgb(255, 0, 0)">IR中机器指令的op</span>，产生对应微程序起始地址，送入uPC。
3.<span style="color:rgb(255, 0, 0)">顺序执行</span>，uPC+1
4.返回循环。
### 下地址字段法（断定法）


顺序执行
对于增量方式：uPC+1；
断定方式：每条微指令的<span style="color:rgb(255, 0, 0)">下地址字段</span>中指出下一条微指令地址。

条件分枝：
增量方式：修改uPC
断定方式：微指令的下地址字段指定的转移目标地址。

uPC的位数为k,那么总的微指令条数最多为$2^k$（包含公共取指微指令！）
uIR位数为一条微指令的位数，比如32位说明一条微指令4B。

# 微指令

微指令存储在控制存储器！
### 水平型微指令
并行操作能力强，效率高，灵活
1.直接编码
简单直观，效率高！无需译码！但是微指令字长过长！
2.字段直接编码。互斥性微命令组合在同一字段中。
3.隐式编码。一个字段某些微命令需要另一个字段某些微命令解释。缩短了微指令字长，但是削弱了微指令并行控制能力。

### 垂直型微指令
并行能力较差，执行时间长。
采用微操作码编译法，由微操作码指定微指令功能。
优点：微指令段、简单、规整，便于编写微程序。
缺点：微程序长，执行速度慢，工作效率低。

在微程序控制方式中，以下说法正确的是（B）
Ⅰ. 采用微程序控制器的处理器称为微处理器
Ⅱ. 每条机器指令由一段微程序来执行
Ⅲ. 在微指令的编码中、效率最低的是直接编码方式
Ⅳ. 水平型微指令能充分利用数据通路的并行结构。
A. Ⅰ、ⅡB. Ⅱ、ⅣC. Ⅰ、ⅢD. Ⅱ、Ⅳ
