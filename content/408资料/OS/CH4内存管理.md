## 程序链接与装入

高级语言—编译程序—>汇编语言—汇编程序—>机器语言—链接程序—>可执行文件。或者高级语言—编译程序—>机器语言
>[!概念]
1️⃣编译：由编译程序将用户源代码翻译成若干目标模块
2️⃣链接：由链接程序将这些目标模块及其所需的库函数合并，形成完整的装入模块。各个模块内的**相对地址要修改成装入模块的逻辑地址**。
3️⃣装入（加载）：由装入程序将该装入模块加载入**内存**，并启动其执行。

链接方式：（链接发生的时机分类，什么时候链接？）
1️⃣静态链接（**装入前链接完了**）：**程序运行之前**将各目标模块及其所需库函数链接成一个完整的装入模块（可执行文件），此后不
再拆分。
特点：1.**地址调整**：各模块编译后均以0位起始地址，链接时需根据其在装入模块中的实际位置，将内部地址统一加上偏移量。2.**外部符号解析**:将模块间引用的外部符号（比如函数名）替换为确定的地址。
2️⃣装入时动态链接（**边装入边链接**）
将程序编译后生成的目标模块，在装入内存时采用**边装入边链接**的方式。当装入某个目标模块时，若遇到对外部模块的调用，则装入程序会立即查找并装入相应的外部目标模块，并替换其中的外部符号。
特点：1.**方便修改和更新**。静态链接只要任何一个模块改了一点，就必须重新打包、重新编译整个程序。装入时动态链接只需要单独换掉这个模块。2.**便于实现对于目标模块的共享**。静态链接每个应用程序包含其依赖模块的完整副本，无法共享（若100个程序用到printf，磁盘就会有100个printf副本）。装入时动态链接方式，OS可将同一个目标模块链接到多个应用程序中，实现共享。可节省内存空间。
具体来说，即printf模块在外存只有一个副本，在内存也只有一份代码(通常只读)，第二个程序要printf时，不加载新的副本，让第二个程序的地址空间指向内存中已由的printf。

3️⃣运行时动态链接（**已装入完成，运行时链接**）
仅当需要掉入某个尚未装入内存的目标模块时，OS才动态加载并链接该模块。**程序中未使用的模块不会被装入内存，也不会链接。** 特点：加快程序装入过程，且更节省内存空间。

装入方式（什么时候转换地址）：
1️⃣绝对装入（==地址装入内存前==就已经修改）
仅适用于**单道程序环境**，**编译直接生成的就是绝对地址**。逻辑地址就是物理地址。绝对地址也可由程序直接指定，但缺乏灵活性。

2️⃣静态重定位（可重定位装入，==**程序装入内存时**==修改逻辑地址为物理地址）
装入内存时一次性修改所有指令和数据中的逻辑地址，使其变为物理地址。**装入后程序位置固定，运行中无法移动。**

3️⃣动态重定位（动态运行时装入，==**运行过程中**==实现逻辑地址转物理地址）
装入内存时仍然是逻辑地址，只有运行过程中通过**重定位寄存器**动态计算物理地址：$物理地址=基址（重定位寄存器内容）+逻辑地址$。这是基址寻址。特点：便于操作系统进行**紧凑**，从而有效减少外部碎片，提高内存分配灵活性，**允许在运行期间动态调整内存布局**。只需要修改重定位寄存器内容。


## 内存保护
确保各进程有独立内存空间，内存保护机制需在内存分配前防止用户进程破坏OS，同时避免用户进程互相干扰。由==**OS和硬件共同实现**==。
方法：
1️⃣**在CPU设置一对上下限寄存器**
2️⃣**重定位寄存器和界地址寄存器**实现越界检查。
CPU给出逻辑地址LA, 需要物理地址PA
```
if LA >= 界地址寄存器:
	地址错误,越界异常;
else:
	PA = (重定位寄存器) + LA;
```
## 内存空间管理
#### 内存连续分配
单一连续分配（仅内部碎片）
内存划分为系统区+用户区。用户区仅允许一道程序运行（程序独占整个用户区）。优点：结构简单，无外部碎片，无须内存保护机制。缺点：仅适用单用户，单任务OS，存在内部碎片，效率低。

固定分区分配（仅内部碎片）
多道程序存储管理。OS维护一张分区使用表，将用户区提前分成固定的分区。缺点：大内存程序无法放入，且内部碎片多。

动态分区分配（仅外部碎片）
空闲分区链（表），根据进程的大小动态建立分区。分区大小数目都可变。
1️⃣基于顺序搜索（只产生外部碎片）

| 分配算法             | 分区排列方式       | 实现方法                          | 优点             | 缺点                      |
| ---------------- | ------------ | ----------------------------- | -------------- | ----------------------- |
| 首次适应算法           | 地址递增排列       | 第一个合适的放进去                     | 高地址大分区被保留      | 每次要从链表头开始查找，增加查找开销      |
| 邻近适应算法（循环首次适应算法） | 地址递增排列（循环版本） | 每次从上次查找结束的位置开始找，找到第一个合适的分区放进去 | 减少了对低地址区域的重复扫描 | 难以支持后续大作业的装入，性能不如首次适应算法 |
| 最佳适应算法           | 容量递增排列       | 优先分配能满足的最小的                   | 尽量保存大分区        | 最容易产生难以利用的外部碎片，性能差      |
| 最坏适应算法           | 容量递减排列       | 优先分配能满足的最大的                   | 减少小碎片          | 大分区很快被瓜分，不利于大进程，性能差     |
内存回收：
1.回收区和前一空闲分区相邻，两者合并，更新前一分区大小。
2.回收区与后一空闲分区相邻，两者合并，更新后一分区起始地址和大小。
3.回收区与前后两个空闲均相邻，三者合并，更新前一分区大小，删除后一分区表项。
4.回收区不与任何空闲分区相邻，新建表项，记录起始地址和大小，插入空闲分区链。

2️⃣基于索引搜索（大中型系统，可能产生内部碎片考频低）
快速适应算法
预先把空闲内存分成多个固定尺寸剋别链表。1根据作业大小在索引表找到能装下它的最小尺寸链表2直接从链表头部取第一个空闲分区分配给进程。。优点：效率高，无外部碎片；缺点：开销大

伙伴系统Buddy算法
所有内存分区大小是$2^k$
假设进程要60MB,
```
先找满足$2^{k-1} < 60MB \le 2^k$
if(64MB有):
	直接分配;
else:找更大的链，找到后二分。128MB->64+64
```

哈希算法
以空闲分区大小为关键字构建哈希表。

紧凑技术：要求系统支持**动态重定位**
#### 内存非连续分配
逻辑/物理地址空间 注意：页号都从0开始！
逻辑：页；物理：页框 页大小=页框大小
$逻辑地址  {\div} 页的存储单元个数 = 页号......页内地址$
$物理地址 \div 物理页存储单元个数 = 物理页号......页内地址$
### 分页存储
##### 逻辑转物理流程：（重要！）

1️⃣根据逻辑地址计算页号页内偏移量，逻辑地址  $\div$ 页的存储单元个数 = 页号......页内地址。
2️⃣判断页号是否越界，若$页号P\ge 页表长度M$,则产生**越界中断**;否则继续执行。
3️⃣**根据页号P查找页表**，找出对应页表项的物理块号(页框号)。
$页表项地址 = 页表基址F + 页号P \times 页表项长度$，取出该页表项中的**物理块号（页框号）b**

**页表项构成:其他信息位 + 物理页框号位**
**页表由每个进程维护一个**，且**所有进程的页表都驻留在内存的内核空间**！
$页表大小 = 页表项大小 \times 页表项个数$
$2^P = 程序页数 = 页表项个数$，P为页号。
例题:按字节编址，逻辑地址和物理地址都是32b，页表项大小4B，一级分页，页号20b+页内偏移12b。求页大小，页表最大大小。

**硬件(MMU)完成**：逻辑地址->物理地址
**操作系统**：页表/段表建立，更新，缺页中断处理，权限检查异常处理


### 二级页表
最高级页表不能超过一页。形式：+代表拼接
一级页号（页目录号）P1+二级页号P2+页内地址d
$2^{P1} = 一级页表项数 = 二级页表的表数$
$2^{P2} = 一页二级页表的页表项数$
$P1 + P2 = 原来的页号,2^{P1+P2} = 所有二级页表页表项数 = 程序的总页数$

#### 页表项起始地址
一级页表项地址 放在 **外部页表寄存器**中
$一级页表项地址 = 一级页表（外部页表）始址 + P1 \times 页表项长度$
$二级页表项地址 = 二级页表（外部页表）始址 + P2 \times 页表项长度$

n级页表最多页:$(2^p)^n$
例:256TB逻辑地址至少需要几级页表？4

#### 快表TLB（SRAM）
快表:专门用来存页表项的高速缓冲存储器。
![[Pasted image 20260823111643.png]]
```
输入：逻辑地址 A = (P, W)，
页表寄存器PTR = (页表基址 F，页表长度 M)
TLB
输出：物理地址 PA

1. 若 P >= M：
       越界中断，结束。

2. 查 TLB：
       TLB hit：
           取页框号 b = TLB[P].页框号
           转第 6 步，直接取PA。
       TLB miss：
           转第 3 步，访问内存页表。
3. 访问内存页表：
       页表项地址 = F + P × 页表项大小
       读页表项。

4. 检查页表项有效位：
       若有效位 == 0：
           产生缺页中断，由操作系统调页；
           调页完成后重新执行该指令（或继续流程）。
       若有效位 == 1：
           取页框号 b = 页表项.页框号。

5. 更新 TLB：
       将 (P, b) 加入 TLB；
       若 TLB 满，按替换策略淘汰一项。

6. 生成物理地址：
       PA = 拼接(b, W)   // 若页面大小为 2^k，可用 PA = (b << k) | W
       或等价地：PA = b × 页面大小 + W

7. 访问物理地址 PA。
```
TLB miss时,MMU通过TWU查询页表,如果页命中，则发送物理地址给cache。

#### 地址映射
主存物理地址->cache：
```
主存物理地址 = 主存(物理)块号 + 块内地址
直接相联:主存物理地址 = Tag + cache行号 + 块内地址;
组相联:主存物理地址 = Tag + cache组号 + 块内地址;
全相联:主存物理地址 = Tag + 块内地址;
```
逻辑地址->TLB：
```
逻辑地址 = 逻辑页号 + 块内地址
直接相联:逻辑地址 = Tag + TLB行号 + 块内地址;
组相联:逻辑地址 = Tag + TLB号 + 块内地址;
全相联:逻辑地址 = Tag + 页内地址;
```

### 分段存储

段式虚拟存储器按"段"在内存与外存进行信息交换。**分段方式对低级语言程序员和编译器是可见的**。每个段有自己的长度。
段式存储地址结构 : (段号S,段内偏移量W)
段表：负责逻辑段->物理内存区；段表起始地址 由  段表基址寄存器给出。
段表项结构：(段号,段长，本段在物理地址的始址)
![[Pasted image 20260823112850.png]]
地址转换:
```
输入:逻辑地址A=(S,W),段表寄存器(段表始址F，段表长度M),
输出:物理地址PA
1. 从逻辑地址 A 中取出段号 S 和段内偏移 W。
2. 若 S >= M：
       段号越界中断，结束。
3. 计算段表项地址：
       段表项地址 = F + S × 段表项大小
4. 访问内存段表，读取段表项，得到：
       段基址 b 段长 L
       有效位/存在位
       （可能还有保护位等）
5. 检查有效位：
       若有效位 == 0：
           产生缺段中断，由操作系统调入该段；
           调段完成后重新执行该指令或继续流程。
       若有效位 == 1：
           继续下一步。
6. 检查段内偏移：
       若 W >= L：
           产生段内偏移越界中断，结束。
7. 检查访问权限：
       若访问类型不合法，例如写只读段，则产生保护中断。
8. 生成物理地址：
       PA = b + W
9. 访问物理地址 PA。
```

>【真题2016】某进程段表内容如下:访问段号=2，段内地址=400的逻辑地址，转换结果为(D)。

| 1   | 200 | ...    | 读写  | 不在内存 |

tips:分段系统的保护机制1️⃣地址越界保护2️⃣存取控制保护（权限）
段页的区分:

|     | 分页                                         | 分段                      |
| --- | ------------------------------------------ | ----------------------- |
| 目的  | 信息的物理单位，分页由OS实现，用户对页“透明”（不可见）。离散分配，内存利用率高。 | 信息的逻辑单位，对低级语言程序员和编译器可见。 |
| 长度  | 一页大小固定                                     | 段大小不固定，由程序决定            |
| 地址  | 一维的地址                                      | 二维，段名+段内地址              |
| 碎片  | 有内部碎片，无外部碎片                                | 有外部碎片，无内部碎片             |

#### 页面共享
分页和分段系统都允许多个进程共享代码与公共数据。
分页系统共享：共享进程中，**将共享页对应的页表项指向同个内存块**。由于系统自动划分页，因此会造成共享内容与非共享内容共处一页，使信息共享困难。
分段系统共享：建立共享段表。一般都是只读代码段。

### 段页式存储器
先分段再分页。分页管理物理主存，分段管理用户地址空间。
逻辑地址结构: 段号+页号+页内地址；
物理地址结构：物理页号+页内地址；
![[Pasted image 20260823125047.png]]
程序整体只有一张段表，每个段对应一个页表。
地址变换过程
```
A = ( S , P , W )
S：段号，P：段内页号，W：页内偏移
段表项起始地址 = F + S*段表项长度;
输入：逻辑地址 A = (S, P, W)
      段表始址 F
      段表长度 M
输出：物理地址 PA
1.从逻辑地址A中取出S,P,W;
2.若S>=M:
	产生段号越界异常，结束。
3.计算段表项地址 = F + S × 段表项大小
访问段表项，获得段表有效位，页表基址，页表长度，访问权限等。
4.检查段表项有效位:
	若 段表有效位 == 0:
		缺段异常，OS将该段调入内存;
		继续流程;
5.检查页号越界:
	若P >= 页表长度:
		产生页号越界异常，结束。
6.计算页表项地址 = 页表基址 + P × 页表项大小
	访问页表项，获得页表项有效位，页框号b，权限位等

7.检查页表项有效位
	若页表项有效位 == 0：
	    缺页异常，由操作系统将该页调入内存。
		继续流程;
8,9: 取出b = 页表项.页框号，生成物理地址PA = b * 页面大小 + W;访存。
```
例题:段页式存储器，cpu每次从内存取一次数据需要访问(3)次内存。

$2^S = 段表项个数 = 程序段数 = 页表个数$
$2^P = 一张页表最多页表项数 = 一个段内最多页数$
$2^{S+P} = 程序最多总页数$

##### 驻留集和工作集:
驻留集:给进程分配的物理页面集合。虚拟存储器系统中，驻留集大小<进程总大小。
工作集:某段时间间隔内，进程实际访问页面的集合。

| 页号  | 物理页号 | 状态位P | 访问字段A | 修改位(脏位)M | 外存地址 |
| --- | ---- | ---- | ----- | -------- | ---- |
|     |      |      |       |          |      |
状态位=0:缺页异常
#### 缺页异常
缺页中断(异常)特点:
1.在指令执行期间出发。2.一条指令执行过程中可能引起多次缺页中断。

#### 地址转换
1.检索快表，若命中，**从相应表项取出该页页框号，并置访问位=1。如果是写操作，置修改位=1.**
2.若快表未命中，访问页表。若该页在内存中(存在位=1)，从相应表项取出物理块号，将该页表项装入快表;若快表已满，按照置换算法淘汰一项。
3.若页不在内存，触发缺页中断(异常)。OS把页从外存掉入内存或置换，更新页表和TLB，随后重新执行地址变换以获得物理块号。
4.**将获得的页框号与页内地址拼接，形成物理地址，用于访存**。
```c

开始：

        return
    // 查询快表TLB
    TLB_hit = 查询快表(P)
    if TLB_hit == true:

    else:

        页表项 = 访问内存页表[P]
        if 页表项有效位 == 0:
            // 缺页，进入缺页中断处理
            保留CPU现场
            if 内存全部页框已满:
                选出要换出的页
                if 换出页的修改位 == 1:
                    将该页写回外存
            // 把缺失页面从外存读入内存页框
            OS发出I/O命令，启动硬件I/O
            将缺页从外存调入内存
            修改内存页表对应表项(有效位、页框号)
            goto 开始  // 中断返回，重新执行地址变换
        // 页在内存，把页表项写入快表
        更新快表TLB[P] = 页表项

    // 页面在内存
    修改页表项：访问位置1；若写操作则修改位置1
    物理地址 = 页框号 << 页内偏移位数 | offset
    使用物理地址访问内存
结束
```

#### 页框分配
分配策略
1.固定分配：OS为每个进程分配**固定数目大小页框**。即**驻留集大小固定不变。**
2.可变分配：OS先为每个进程分配一定数目页框，在程序运行过程中，可以动态改变页框数目。即**驻留集大小可变**。
页框置换策略：
1.局部置换：缺页时，**只能选择当前进程中的驻留集页框进行置换**
2.全局置换：OS**保持一个空闲页框队列**，若某进程发生缺页，从空闲页框取出一块分配给该进程。如果空闲页框没有了，从**所有页框中选择页面换出到外存，再将页框分配给缺页的进程**。

##### 固定分配局部置换
为每个进程分配固定数量页框，整个运行期不变。若进程运行时缺页，只能在本进程内存页面（驻留集）中选出一个进行换出，然后调入页。
缺点：驻留集固定，太少缺页多，太多浪费和减少并发。
固定分配算法的驻留集确定策略：平均分配，按比例分配，优先权分配。通常可将一部分比例分配，另一部分依据优先权动态分配。
最小页框数：保证==**进程正常运行所需的最少页框数量**==。取决于**指令格式，功能，寻址方式**。
极端情况：一条指令跨越2页，2个操作数分别跨越2页。就要6页。

	

##### 可变分配全局置换
OS为每个进程分配一定数量页框，还会保持一个空闲页框队列。若缺页发生，可从空闲页框取出一块分配给该进程。如果空闲页框没有了，从所有页框选择页面换出到外存，再将页框分配给缺页进程。**全局置换必须要求可变分配！！**
优点：灵活，可动态扩充进程的驻留集。缺点：每次缺页都要分配新页框，驻留集膨胀，削弱系统并发能力。

##### 可变分配局部置换
OS为每个进程分配一定数量页框，**若缺页发生，只允许从当前进程的页框中选出一个换出外存**。如果进程**频繁缺页，动态增加页框**。如果缺页率很低或不缺页，适当减少分配页框。
优点：有效抑制进程频繁调页，可以保持系统**多道程序的并发率较高**。缺点：开销较大。


####  页面的调入
##### 调页时机
###### 预调页策略 （了解）
根据**局部性原理，一次调入若干相邻页面通常比逐页调入更高效**。但也会造成内存浪费，故**系统可尝试进程近期可能访问的页面并预先调入**。
###### 请求调页策略
进程出发缺页中断时，OS将所需页面调入内存。缺点是每次仅调入一页，导致磁盘I/O开销较大。

若内存已满，1.按置换算法选出一页换出。若修改位=0，直接丢弃。若修改位=1，先写回swap区，再释放页框。2.发起磁盘I/O调入所缺页面，更新页表项，置存在位=1.



#### 页面置换算法
##### 最佳置换算法(OPT)
在最长时间内不再访问的页面。但是实际中无法实现。
##### 先进先出置换算法(FIFO)
实现简单。按调入时间组成队列。缺点：未利用局部性原理，性能可能较差
Belady现象:仅出现在FIFO中。有时候会出现分配的页面数(驻留集)越大，缺页率也提升的现象。
##### 最近最久未使用算法(LRU)
选择最近最久没被访问的页面淘汰。只要在访问序列往前找谁最久没被使用。
实现方法：在页表项中，访问字段记录自上次被访问以来所经历的时间。当需要淘汰一个页面时，选择现有页面中t最大的。

例题，LRU，访问序列1878272183821317131，内存容量4个页，则缺页次数：6。
注意:缺页次数不等于页面置换次数！！

##### 时钟置换算法(CLOCK) = NRU最近不用
检查访问页，若为0淘汰；若为1置为0，暂不换出，继续检查下一个页面。如果所有帧的使用位都是1，则指针循环一周将所有使用位置0.口诀：循环找0，全1则变全0.


##### 改进型时钟置换算法(CLOCK)
在之前的CLOCK算法上除了访问位，增加修改位
（0，0）最近没有使用也没有修改；（0，1）修改过但最近没有使用（1，0）使用过但没有被修改下一轮将再被使用，（1，1）使用过也修改过，下一轮页面置换最后的选择。
Round1:扫描到第一个(0,0)帧用于替换。本轮扫描不修改任何标志位。
Round2:第一轮失败，查找第一个(0,1)替换。扫描过的帧访问位设置为0；
round3：第二轮失败，查找第一个(0,0),不修改任何标志。
round4:第三轮失败，查找第一个(0,1)帧替换。
r2中所有(1,0)变成(0,0);(1,1)变(0,1)

##### 内存映射文件
定义：OS向进程提供的系统调用机制，是<span style="color:rgb(255, 0, 0)">进程虚拟地址空间和磁盘文件的直接映射</span>。

**mmap不会立即拷贝文件到内存，缺页中断才加载（按需调页）**
如果是私有映射，不会写回文件。共享映射会写回。
