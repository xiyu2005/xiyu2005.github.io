文件描述符fd的本质：文件描述符是进程打开文件表中的索引，是内核提供给用户态的抽象句柄，用于间接引用内核管理的打开文件实例。​

进程（用户级,但是保存在内核态内存中）文件描述符表的数组下标。是句柄，是访问凭证，是资源标识符。用户态只能通过系统调用，例如：
`int fd = open("a.txt", O_RDONLY);``read(fd, buf, 100);`
1. 用户态调用 `open`，发生系统调用，陷入内核；
2. 内核在当前进程的 `files_struct` 中分配一个空闲表项，得到 `fd`；
3. 内核把 `fd` 返回给用户态；
4. 之后用户态调用 `read(fd,...)`，再次陷入内核；
5. 内核根据 `fd` 查当前进程的 `files_struct`，找到对应 `file` 结构；
6. 内核访问 `file` 结构和 inode，完成读写。

权限位：权限矩阵，不互斥，不能用$2^n$算位数，权限位只保存在内存inode，不是目录文件里。

Linux 中执行 `ls -l` 能看到某个文件的权限，原因是：
1. `ls` 先读取目录文件，得到目录项列表；
2. 目录项中主要包含 **文件名** 和 **inode 号**，一般不包括权限、大小、时间等详细信息；
3. `ls` 根据每个目录项中的 inode 号，调用 `stat()` 等系统调用，让内核去读取对应 inode；
4. inode 中的 `mode` 字段包含文件类型和访问权限位，例如 `rw-r--r--`；
5. `ls` 再把这些信息格式化输出。

软硬连接：

| 项目                | 硬链接       | 软链接          |
| ----------------- | --------- | ------------ |
| 是否共享 inode        | 是         | 否，有自己的 inode |
| 是否共享数据块           | 是         | 否，数据块存路径     |
| 是否增加目标 inode 链接计数 | 是         | 否            |
| 能否跨文件系统           | 不能        | 能            |
| 能否链接目录            | 通常不能      | 能            |
| 删除目标后             | 文件仍存在     | 符号链接失效       |
| 本质                | 同一文件的多个名字 | 指向目标路径的独立文件  |

 **硬链接**：同一个 inode 的多个目录项，本质是同一文件的多个名字。
 **软链接**：一个独立文件，内容存放目标路径，本质是“快捷方式”。


程序控制访问:用户级IO程序->设备无关程序->设备驱动程序->设备无关程序->用户程序
**CPU 发命令 → 读状态 → 忙等待 → 设备就绪 → 传一个数据单位 → 再查状态 → 继续传输，直到完成。** cpu处于忙等待，效率低。

中断IO方式：用户级IO程序->设备无关程序->设备驱动程序->IO硬件->中断处理程序->设备驱动程序->设备无关程序->用户程序

设备独立性软件=设备无关软件，功能：映射(逻辑设备转物理设备)，保护(检查权限)，分块(提供统一的逻辑数据块大小，防止设备物理块差异)，缓冲(缓冲区)，分配(分配设备)；
独占设备:打印机，串口；共享设备:硬盘，网卡
共享的含义：宏观上通过调度实现共享
设备驱动程序：转换抽象要求为具体，校验IO请求，检查设备状态，传送必要参数，启动IO设备。
设备驱动程序管理的资源：IO端口号/内存地址，设备缓冲区内存，中断号

DMA 方式读磁盘的典型流程如下：

用户进程 P 发起 read() 系统调用；
内核设备驱动程序设置 DMA 参数，启动磁盘读操作；
进程 P 因等待 I/O 被阻塞；
磁盘控制器通过 DMA 方式将数据从磁盘直接传输到内核缓冲区；
DMA 传输完成后，磁盘控制器发出 DMA 完成中断；
CPU 接收到该中断，进入中断处理程序。

设备分配过程中访问相关控制表的顺序
(逻辑设备表LDB)->系统设备表 SDT->设备控制表 DCT->控制器控制表 COCT->通道控制表 CHCT
1. **查找系统设备表 SDT**  
    根据进程请求的设备名或逻辑设备名，在系统设备表 SDT 中找到对应的表项，得到该设备的设备控制表 DCT 指针或设备类型等信息。
2. **访问设备控制表 DCT**  
    根据 SDT 中的指针找到该设备的 DCT，检查设备状态：
    - 如果设备忙，则将该进程加入 DCT 中的设备等待队列；
    - 如果设备空闲，则分配给该进程，并记录占用信息。
3. **访问控制器控制表 COCT**  
    从 DCT 中找到与设备相连的控制器，进而访问 COCT，检查控制器是否空闲：
    - 若控制器忙，则进程进入控制器等待队列；
    - 若控制器空闲，则分配该控制器。
4. **访问通道控制表 CHCT**  
    如果系统中还有 I/O 通道，则从 COCT 找到相连的通道，访问 CHCT，检查通道是否空闲：
    - 若通道忙，则进程进入通道等待队列；
    - 若通道空闲，则分配通道。

**主设备号**和**从设备号**：主设备号标识设备的**类型**，决定使用哪一个设备驱动程序。从设备号标识**同一主设备号下的不同设备实例**，由设备驱动程序解释。
