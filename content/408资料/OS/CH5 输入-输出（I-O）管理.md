# （一）I/O管理基础
## 设备的基本概念
I/O设备是执行输入/输出操作的机械与电子部件，是计算机系统中种类最多、速度差异最大的部分。从每秒几字节的键盘到每秒数百兆字节的磁盘，跨度可达百万倍，因此CPU无法直接与设备“对接”，必须通过中间层进行适配。
从层次上看，一条I/O通路上存在三个不同粒度的实体：

|层次|指什么|粒度|
|---|---|---|
|**I/O设备**|执行具体I/O操作的机械部件（如磁盘的盘片与磁头、键盘的按键）|一台设备|
|**设备控制器（I/O接口）**|CPU与设备之间的电子部件，负责吸收设备差异、执行控制|一块控制器，可挂1~多台设备|
|**I/O端口**|控制器内部可被CPU直接寻址的寄存器|一个寄存器|

**控制器（接口）是硬件意义上的“中间层”，端口是这一层中CPU真正“够得着”的窗口**；设备控制器内部包含若干个I/O端口。


### 设备的分类
408中设备分类有几套并行的标准，每套标准服务于OS的不同决策，不能只记名称而忽略分类的用途。

**1. 按信息交换单位：块设备 vs 字符设备（最核心）**

二者的分界判据不是“快慢”，而是**能不能寻址**。

				块设备	         字符设备
交换单位	固定大小的数据块（如512B）	单个字符
可寻址性	可寻址，可随机访问任意块	不可寻址，只能顺序收发
典型例子	磁盘、SSD、光盘	键盘、打印机、串口
数据组织	以块为单位组织与传输	以字符流形式串行传输

打印机虽然速度不一定“快”，但它不可寻址，无法“重打第37块”，因此属于字符设备。块设备可寻址、传输速率通常较高，常采用DMA方式；字符设备不可寻址、速率较低，常采用中断驱动方式。

**2. 按传输速率：低速 / 中速 / 高速**

低速设备（键盘、鼠标）约每秒几至数百字节；中速设备（行式打印机、激光打印机）约数千至数十万字节；高速设备（磁盘、磁带、光盘）可达数十万字节以上。这一分类主要影响I/O控制方式与缓冲策略的选择：低速设备可轮询，高速设备必须考虑DMA。

**3. 按共享属性：独占 / 共享 / 虚拟**
独占设备同一时刻只能由一个进程占用（如打印机、磁带机）；共享设备在一段时间内可被多个进程同时访问（如磁盘）；虚拟设备是通过**SPOOLing技术**将独占设备改造为逻辑上的共享设备，使一台物理设备可同时面向多个进程。
**4. 按使用特性：存储设备 / 输入输出设备 / 交互式设备**
存储设备（磁盘、光盘）走文件系统路径；输入输出与交互式设备走设备管理路径。



### I/O接口
**概念。** I/O接口又称I/O控制器、设备控制器、适配器，是介于CPU与设备之间的硬件层，负责协调二者之间的数据传输。教材中“I/O接口”与“设备控制器”在多数语境下可近似视为同义，指的是同一块控制逻辑整体。[](https://www.cnblogs.com/lordtianqiyi/p/17694109.html#1)

**核心功能。** 接口存在的根本理由是**吸收CPU与设备之间的不匹配**——速度不匹配、信号格式不匹配、时序不匹配。围绕这一目标，接口必须具备的功能包括：

- **数据缓冲**：通过数据缓冲寄存器/缓冲区，让高速CPU不必等待低速设备；
- **地址识别与设备选择**：一块控制器可能挂多台设备，需通过地址译码选中目标设备与目标寄存器；
- **接收和识别命令**：CPU发出“读/写”等命令后，由控制逻辑译码并执行；
- **状态标识与报告**：通过状态寄存器向CPU反映设备“就绪/忙/出错”等状态；
- **信号格式转换**：串/并转换、电平转换等；
- **差错控制**：在靠近硬件的层面检测并报告传输错误。
- 
**结构组成。** 典型I/O接口包含三部分：

1. **与CPU侧的接口**：数据线、地址线、控制线三类信号线。数据线连接数据寄存器与控制/状态寄存器；
2. **与设备侧的接口**：一个控制器可连多台设备，每个设备接口上同样有数据、控制、状态三类信号；
3. **I/O逻辑**：负责地址译码、命令识别与设备控制。

> 注意区分：I/O接口是**硬件层**的概念；操作系统中的“输入输出应用程序接口”（字符设备接口、块设备接口、网络设备接口）是**软件层API**，二者只是中文同名，不在同一层面。[](https://www.codebrick.tech/os-full/posts/io/device-concept)



### I/O端口

**概念。** I/O端口是设备控制器（I/O接口）内部**可被CPU直接访问的寄存器**。从控制器内部看，它是一个有含义的寄存器；从CPU的地址空间看，它有一个地址、可被寻址。CPU的I/O指令**只能管到端口这一层**，端口以下与设备的具体交互由控制器自治。[](https://www.cnblogs.com/lordtianqiyi/p/17694109.html#1)[](https://www.codebrick.tech/exam-408/q/co/2017/21)

**三类端口及其操作方向（高频考点）：**

| 端口类型     | 存放内容          | CPU可执行的操作 |
| -------- | ------------- | --------- |
| **数据端口** | 待传送的数据，命令     | **读 / 写** |
| **状态端口** | 设备就绪、忙、出错等状态  | **只读**    |
| **控制端口** | 启动、停止、模式等控制命令 | **只写**    |
数据和状态端口可合并

记忆抓手：数据双向，状态只进CPU，控制只出CPU。
**端口编址方式。** CPU要访问端口，就必须为端口分配地址。两种编址方式的**判据极简**：看访问设备寄存器用的是**专用I/O指令（IN/OUT等）** 还是**普通访存指令（load/store）**。前者对应独立编址，后者对应统一编址。[](https://www.codebrick.tech/os-full/posts/io/device-concept)

||**独立编址（I/O映射）**|**统一编址（内存映像I/O）**|
|---|---|---|
|地址空间|端口自成一套地址空间，与内存互不干扰|端口占用内存地址空间的一段（通常高端）|
|访问指令|必须用专用I/O指令|普通访存指令即可|
|硬件代价|需要额外的控制线区分访存与访端口|不需要额外控制线，但**切走一块内存地址空间**|
|编程 / 保护|专用I/O指令是特权指令，天然限内核态|一套指令通吃，灵活；靠页表权限位保护|

独立编址的端口地址译码较简单，I/O指令短、执行快；统一编址则指令类型丰富、编址空间大，但会减少可用主存容量，且程序中不易区分访存与访端口。早期32位系统实际可用内存常略低于4 GB，原因之一就是设备寄存器占用了内存地址空间的高端段。[](https://www.codebrick.tech/os-full/posts/io/device-concept)

---

**一句话收束：** 设备是“干活的”，控制器/接口是“管设备的”，端口是控制器中“CPU能够伸手够到的寄存器”；块与字符看可寻址性，独立与统一编址看指令。
