### 随机接入协议
### ALOHA协议
包括纯ALOHA和时隙ALOHA协议。
#### 纯ALOHA协议
发送方启动计时器判断帧是否碰撞。一定时间后还没有接收到ACK，就以独立的概率p重发帧，如果不重传，等待t0，不充传的概率是1-p，重新抉择，要么p概率传，要么1-p概率再等。

#### 时隙ALOHA协议
划分为t0的时隙，结点只能在时隙起点开始传输帧。结点时间同步，每个节点都知道时隙何时开始。p概率再下一个时隙重传。
**时隙ALOHA协议的信道利用率高于纯ALOHA。**

### 载波监听多路访问（CSMA）协议
1.说话前先听。（节点在传输前先监听信道，载波监听）
2.如果与他人同时开始说话，停止说。（碰撞检测）
CSMA/CD会满足1，2.
#### 三种CSMA协议
##### 1-坚持CSMA
空闲：立即发数据
忙：继续坚持监听
##### 非坚持CSMA
空闲：立即发数据
忙：放弃监听，等一个随机时间再监听
##### p-坚持CSMA
空闲：概率p发，1-p推迟到下一个时隙再判断。
忙：持续监听，直到信道空闲。

非坚持CSMA相比1-坚持CSMA，降低了多个站点在信道空闲后立即发送导致的冲突概率。
### 具有碰撞检测（collision detection）的CSMA协议：CSMA/CD
**CSMA/CD = 先听后发、边发边听、冲突停发、随机重发**，用于**总线型（半双工）以太网**
所以是1-坚持CSMA
争用期：$2\tau = 2 \times 最远两个节点之间的传播时延$

哪些节点的链路层需要运行CSMA/CD协议？同个集线器连接的所有结点，包括半双工的交换机口+主机。

支持CSMA/CD的局域网只能半双工通信。
#### 指数退避算法
1.求争用期$2\tau$
2.从${0,1,...,2^k-1}$挑选一个数$r$,$r \times 争用期$为时间。$k=min(重传次数，10)$
3.重传16次不成功，丢弃该帧。

#### 最短帧长
争用期内结点发送的比特数

### 轮询协议
#### 令牌传递协议
一个节点收到令牌时仅当有一些帧要发送时才持有，否则立即转发给下一个节点。收到令牌如果要传输，发送最大数目的帧，再传递给下一个。

### MAC地址

### ARP协议
每台主机都有一张ARP缓存表，存放IP到MAC地址的映射，动态更新且有老化时间。
以主机B要获取主机C的MAC为例：
（1）主机 B 要向 C 发送数据但 ARP 缓存中没有 C 的映射，B 的 ARP 模块在本局域网内**广播**发送 ARP 请求报文，报文内容为：B 自己的 IP 与 MAC、要查询的目标 IP（C 的 IP），目标 MAC 未知。
（2）局域网内其他所有主机都在链路层收下这个广播帧，将请求中的查询 IP 与自己的 IP 比对。
（3）主机 C 的 IP 与查询 IP 一致，收下请求，把 B 的 IP-MAC 写入自己的缓存，并**单播**返回 ARP响应报文，携带 C 的 IP 与 MAC；其他主机虽然在链路层收下了帧，但 IP 层发现查询 IP 与自身不一致，直接丢弃（但是可以顺便学习 B 的映射）。
（4）主机 B 收到 ARP 响应报文，把 C 的 IP-MAC 写入自己的 ARP 缓存，之后即可发送数据帧。

补充：ARP 请求靠广播、响应靠单播；缓存动态更新、有生存期；ARP 只在本局域网内有效。

| 字段      | 请求报文（B 广播） | 响应报文（C 单播） |
| ------- | ---------- | ---------- |
| 发送方 IP  | B 的 IP     | C 的 IP     |
| 发送方 MAC | B 的 MAC    | C 的 MAC    |
| 目标 IP   | C 的 IP     | B 的 IP     |
| 目标 MAC  | 全 0（未知，待填） | B 的 MAC    |

> 注意：ARP 请求**报文内部**的"目标 MAC"字段填全 0，但封装它的**帧**目的地址是广播地址 FF-FF-FF-FF-FF-FF；响应报文的目标 MAC 填 B 的 MAC，帧目的地址也是 B 的 MAC（单播）。
注意：ARP表都有生存时间TTL，超过会被删除，重复会被更新。
注意：ARP用于解决同一网络内的IP和MAC地址映射。


### 以太网交换机转发和过滤、交换机的自学习
网桥：对收到的帧根据其MAC帧的目的地址进行转发过滤。
以太网（二层）交换机实质上就是多端口网桥。
交换机的工作层：数据链路层，物理层
先记住交换机处理帧的**三种动作**，再配合例子看：

- **泛洪**：目的 MAC 查不到（或为广播地址），向除进入端口外的**所有端口**转发；
- **转发**：查到目的端口，且目的端口 ≠ 进入端口，**只**向该端口转发；
- **过滤**：目的端口 = 进入端口（源、目的在同一端口网段），或帧不应到达其他端口时，**直接丢弃/不转发**。

举例，拓扑：交换机 4 个端口，端口 1 连 A，端口 2 连 B，端口 3 连 C，端口 4 连 D。初始转发表为空，按顺序发生下列事件：

| 步骤  | 事件      | 自学习      | 查表结果           | 交换机动作                             |
| --- | ------- | -------- | -------------- | --------------------------------- |
| ①   | A→B 发帧  | 记 A→端口1  | 查 B 未命中        | **泛洪**：向端口 2、3、4 转发，仅 B 收下，C、D 丢弃 |
| ②   | B→A 回帧  | 记 B→端口2  | 命中 A→端口1，且 1≠2 | **转发**：仅向端口 1 转发，端口 3、4 被**过滤**   |
| ③   | A→B 再发帧 | 刷新 A→端口1 | 命中 B→端口2，且 2≠1 | **转发**：仅向端口 2 转发，C、D 不再收到         |
| ④   | D 发广播帧  | 记 D→端口4  | 目的 MAC 全 1     | **泛洪**：向端口 1、2、3 转发（除进入口 4）       |

- **①是泛洪，②③是转发，②③中 C、D 收不到帧就是过滤效果的体现**：查表命中后，帧不再发往无关端口。
- **同端口过滤**：若 A 和另一台主机 E 经集线器都连在端口 1，A→E 的帧查表发现 E 也在端口 1（等于进入端口），交换机**直接丢弃**，不向任何其他端口转发。
- **自学习依据帧的源 MAC**：任何进入的帧，交换机都记录「源 MAC → 进入端口」；表中已有该条目时刷新其时间戳。
- **转发表动态维护**：条目有老化时间，超时未被刷新即删除，以适应主机移动或换端口。

#### 交换机具有存储转发和直通交换两种方式
存储转发：先缓存再查表转发；
直通交换：收到帧的同时立即按照MAC地址转发

| 对比项     | 存储转发               | 直通交换                  |
| ------- | ------------------ | --------------------- |
| 开始转发的时机 | 收到**整个帧**并校验后      | 只收**前 6 字节**（目的 MAC）后 |
| 转发时延    | 大（≥ 收完整帧时间）        | 小（≈ 查表时间）             |
| 差错检测    | 有 CRC 校验，**丢弃错误帧** | 无校验，**错误帧照常转发**       |
| 缓存需求    | 需缓存完整帧             | 一般无需缓存                |
| 可靠性     | 高                  | 低（错误帧会扩散）             |
| 速率适配    | **支持不同速率端口互连**     | 要求输出速率 ≥ 输入速率，否则只能缓存  |
