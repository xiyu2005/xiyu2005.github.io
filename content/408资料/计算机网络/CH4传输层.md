## 复用和分用
**复用——发送方**  
多个应用进程的数据都交给**同一个传输层协议**（TCP 或 UDP），再交网络层发送。
**分用——接收方**  
传输层收到数据后，根据**目的端口号**把数据**交付给正确的应用进程**。
UDP二元组（目的 IP + 目的端口）无连接；尽最大努力交付
TCP四元组（源 IP + 源端口 + 目的 IP + 目的端口）面向连接，四元组标识。可靠传输

传输层给应用层的SAP：TCP/UDP端口

### UDP校验和
范围：伪首部+UDP首部+数据，伪首部不参与传输
发送方：对所有16bit字进行反码运算循环求和，放入校验和。
接收方，伪首部+数据部分二进制反码求和，如果结果为全1则无差错。
eg
伪首部：0x0A00  0x0001  0x0A00  0x0002  0x0011  0x000C
UDP首部：0x043F  0x000D  0x000C  0x0000(校验和)
数据：  0x0001  0x0002
和为0x187B
故校验和=0xE784，填入发送。
正确传输时，接收端相加为FFFF。


## 可靠数据传输原理
网络层

| 协议       | 标准表述                                     |
| -------- | ---------------------------------------- |
| **IP**   | **无连接、不可靠**的数据报服务（尽力而为交付）                |
| **ICMP** | 差错报告 + 询问报文，**封装在 IP 数据报中**（协议号 1）       |
| **ARP**  | 实现同一局域网内 **IP → MAC** 解析，**广播请求、单播响应**   |
| **DHCP** | **UDP**（服务器 67 / 客户端 68），动态主机配置，**即插即用** |

## 传输层

|协议|标准表述|
|---|---|
|**UDP**|**无连接、不可靠、面向报文**，尽最大努力交付；支持一对一/一对多/多对多；首部 8 B；无流量与拥塞控制|
|**TCP**|**面向连接、可靠、面向字节流**，全双工、一对一；首部最小 20 B；有流量控制和拥塞控制|

### 停止等待协议

### 后退N帧协议GBN
发送窗口序号范围$[0,2^k-1]$
接收窗口长度WR=1，因此接收方只能按序接受分组。
发送窗口长度$1< Wt\le2^k-1$。WT=1时退化为停止等待协议。

发送方超时：**重传从丢失帧起的所有已发送未确认帧**（这就是"后退 N 帧"）

接收方采用累积确认：ACK n 表示 n 及之前的帧全部收到。对失序帧	**丢弃**（不缓存），并**重发最后一个正确接收帧的 ACK**

### 选择重传协议SR
发送窗口WT满足$1<WT\le2^{k-1}$,k是分组序号的比特数量
接收窗口WR满足$1<WR\le WT$

**信道好 → GBN 够用；误码率高 → SR 更优**。

滑动窗口协议都会满足发送窗口大小+接收窗口大小<=序号总数。


## 面向连接运输 TCP
#### TCP首部字段

| 字段           | 长度      | 作用                      |
| ------------ | ------- | ----------------------- |
| **源端口**      | 2 B     | 发送方端口号                  |
| **目的端口**     | 2 B     | 接收方端口号（分用依据之一）          |
| **序号 seq**   | 4 B     | 本报文段**数据第一个字节**的编号      |
| **确认号 ack**  | 4 B     | **期望收到的下一个字节**的编号       |
| **数据偏移**     | 4 bit   | 首部长度，**以 4 B 为单位**      |
| 保留           | 6 bit   | 暂时保留（置 0）               |
| **标志位**（6 个） | 各 1 bit | URG、ACK、PSH、RST、SYN、FIN |
| **窗口**       | 2 B     | 接收窗口，用于**流量控制**         |
| **检验和**      | 2 B     | 校验伪首部 + 首部 + 数据         |
| **紧急指针**     | 2 B     | 仅 URG = 1 时有效，指出紧急数据末尾  |
| **选项**       | 0~40 B  | MSS、窗口扩大、时间戳、SACK 等     |
| 填充           | 可变      | 使首部长度为 4 B 的整数倍         |
例题：TCP的最大文件长度？看序号有32位，$2^{32}$B = 4GB


| 标志      | 名称  | 含义                            |
| ------- | --- | ----------------------------- |
| URG     | 紧急  | 紧急指针有效，数据需优先处理                |
| **ACK** | 确认  | 确认号字段有效（**连接建立后所有报文段都必须置 1**） |
| PSH     | 推送  | 尽快交付应用层，不等缓冲区填满               |
| RST     | 复位  | 连接出现严重差错/拒绝连接，**强行释放**        |
| **SYN** | 同步  | 连接请求/接受，**同步序号**              |
| **FIN** | 终止  | 释放连接                          |

TCP首部最小长度为20B。
UDP首部固定8B，TCP最小20B

### TCP拥塞控制
拥塞窗口：cwnd,接收窗口rwnd
待发送数据量$\le \min\{cwnd,rwnd\}$

拥塞感知：1.超时 2.3个冗余ack（初始+后续3个）

慢开始：指数。
拥塞避免：现行增大。

无论什么时候超时：ssthresh = cwnd/2,cwnd = 1;
3个冗余ack:ssthresh = cwnd/2, cwnd=ssthresh;
