# （一）网络层功能
## 1.异构网络互联
(1) 物理层使用的中间设备叫做转发器(repeater)。  
(2) 数据链路层使用的中间设备叫做网桥或桥接器(bridge)，交换机。  
(3) 网络层使用的中间设备叫做路由器(router)。  
(4) 在网络层以上使用的中间设备叫做网关(gateway)。用网关连接两个不兼容的系统需要在高层进行协议的转换。
## 2.路由与转发
转发是指分组从一个输入链路口转移到适当输出链路口的路由器本地动作，通常很短，采用硬件；
路由选择是确定分组从源到目的地所采取的端到端路径的网络范围处理过程，时间长，采用软件。

## 3.SDN基本概念
SDN（软件定义网络）的核心是数据平面与控制平面分离。
**体系结构（三大平面与两大接口**）
应用平面：网络控制应用程序（代表网络的“智力”，如路由算法、负载均衡）。
控制平面：SDN控制器（逻辑上集中，物理上可以分布式部署），维护全局网络状态。
数据平面：SDN交换机（只负责执行流表中的“匹配+动作”）。

北向接口：控制器暴露给上层应用程序的API（用于编程）。
南向接口：控制器与底层交换机之间的通信协议

 **四大关键特征**
- **基于流的转发**：传统路由只看目的IP；SDN交换机可以根据链路层、网络层、传输层等多个首部字段组合进行转发。
- **控制与数据分离**：交换机只做快速转发，控制逻辑在外部服务器上。
- **集中式控制**：控制器在逻辑上是单一的集中实体，掌握全局网络视图。
- **网络可编程**：通过上层应用软件（编程）动态改变网络行为，而不需要去摸物理设备。

## IP地址划分

### 子网划分
**原理**：从传统主机号中借若干位作为子网号，使两级结构（网络号+主机号）变为三级结构（网络号+子网号+主机号）。
**子网掩码作用**：用连续的 1 对应网络号和子网号，连续的 0 对应主机号。将 IP 与掩码按位与，得到子网地址。
**计算方法**：
- 借位数为 n，则子网数 = 2ⁿ（现代无类别路由中全 0/全 1 子网可用）。
- 剩余主机位为 m，每个子网可用主机数 = 2ᵐ − 2。
- 子网地址 = IP ∧ 子网掩码（主机位全 0）。
- 广播地址 = 子网地址中主机位全置 1。
- 主机号 = IP 中除去网络号和子网号的部分。

**例**：192.168.1.0/24 借 3 位，子网掩码 255.255.255.224，子网数 8，每子网可用主机 2⁵−2=30。

### IP 分组跨网段转发完整流程

1. **源主机判断**：用本机掩码与目的 IP 按位与，比较网络号。若相同，说明在同一网段；若不同，则跨网段。
2. **同网段**：直接 ARP 请求目的主机 MAC，封装帧发送。
3. **跨网段**：ARP 请求默认网关 MAC，将帧发给网关。此时帧的目的 MAC 是网关，但 IP 分组的目的 IP 仍是最终目的主机。
4. **路由器逐跳转发**：
    - 路由器收到帧，解封装，取出 IP 分组。
        
    - 用目的 IP 查路由表，按最长前缀匹配找到下一跳和出接口。
        
    - 通过 ARP 获得下一跳 MAC（若缓存无），重新封装二层帧。
        
    - **源 IP、目的 IP 全程不变**；**源 MAC、目的 MAC 逐跳改变**（源 MAC 变为当前出口 MAC，目的 MAC 变为下一跳 MAC）。
5. 重复上述过程，直到最后一跳路由器将帧送达目的主机所在网段，由目的主机接收。


### 无分类编址 CIDR 核心原理
- 取消传统 A/B/C 类及子网概念，将 32 位 IP 地址划分为“网络前缀 + 主机号”。
- 网络前缀长度可变，用斜线记法表示，如 `192.168.1.0/24`。
- 支持路由聚合（超网），将多个连续前缀合并为一个更短前缀，减少路由表项。
- 路由查找采用最长前缀匹配
- 选择与前缀匹配最长的路由条目
### 网络前缀

- **定义**：IP 地址中用于标识网络部分的前若干位。
- **作用**：路由表中依据网络前缀匹配目的地址，决定转发路径。
- **表示方法**：`IP地址/前缀长度`，如 `10.0.0.0/8` 表示前 8 位为网络前缀。

### CIDR 地址块
- **概念**：由网络前缀和前缀长度确定的连续 IP 地址集合。
- **地址块范围**：前缀后全 0 为最小地址，前缀后全 1 为最大地址。
- **主机数量**：若前缀长度为 p，则地址块总地址数 = 2^(32−p)，可用主机数 = 2^(32−p) − 2（去掉全 0 和全 1）    
- **例**：`192.168.0.0/23` 范围 192.168.0.0 ~ 192.168.1.255，总地址 512，可用主机 510。

### 地址掩码与网络前缀的对应关系
- **对应关系**：网络前缀长度 n 对应掩码前 n 位为 1，其余为 0。如 /24 ↔ 255.255.255.0。
- **区别**：网络前缀是长度表示（斜线记法），掩码是具体的 32 位二进制数，用于按位与运算。
- **联系**：两者本质相同，都用于区分网络部分和主机部分；CIDR 中常用前缀长度，子网划分中常用掩码。掩码可转换为前缀长度，反之亦然。

### 路由聚合
路由聚合（Route Aggregation），又称超网（Supernetting），是 CIDR 的核心应用之一。其基本思想是：将多个具有相同下一跳或同一出口的连续网络前缀，合并为一个更短（前缀长度更小）的网络前缀，从而减少路由表条目，提高路由查找效率。

**方法**：将待聚合的多个网络地址写成二进制，找出它们的最长公共前缀。聚合后的网络前缀 = 公共前缀 + 剩余位全部置 0，前缀长度 = 公共前缀的位数。
**示例**：  
192.168.0.0/24 与 192.168.1.0/24  
第三字节：0 = 00000000，1 = 00000001，前 7 位相同，故公共前缀为前 23 位。  
聚合结果：192.168.0.0/23，覆盖范围 192.168.0.0 ~ 192.168.1.255。

## 网络地址转换NAT
### NAT
装有NAT软件的路由器叫做NAT路由器，至少有一个有效的外部全球IP地址。这样才能转化其他私有地址为自己这个。
例题：假定一个 NAT 路由器的公网地址为 205.56.79.35，并且有如下 NAT 表项：

|转换端口|源 IP 地址|源端口|
|---|---|---|
|2025|192.168.32.56|21|
|2057|192.168.32.56|20|
|1892|192.168.48.26|80|
|2256|192.168.55.106|80|

它收到一个源 IP 地址为 192.168.32.56、源端口为 80 的分组，其动作是（ ）
A 转换地址，将源 IP 变为 205.56.79.35，端口变为 2056，然后发送到公网
B 添加一个新的条目，转换 IP 地址及端口然后发送到公网
C 不转发，丢弃该分组
D 直接将分组转发到公网
正确答案是C，不转发，丢弃该分组。原因是这样的，当路由器收到这个分组后，首先会去查NAT表项，发现源IP 192.168.32.56虽然存在，但它对应的源端口只有21和20，并没有80端口的记录。此时就需要看端口是熟知端口还是临时端口。这里的源端口80是一个熟知端口，代表的是内网设备作为服务端提供的服务。在NAT的机制中，熟知端口的表项通常必须由管理员手动配置，用于静态的端口映射。既然表中没有这个80端口的映射，就说明管理员并没有配置它对外提供服务，路由器不会为熟知端口动态生成新条目，因此会直接丢弃该分组。

### 4.ARP协议，DHCP协议与ICMP协议

#### 地址解析协议ARP
每一台主机都有一个ARP高速缓存。
- **同一网段**：源主机广播发送ARP请求（目标MAC为全F），目的主机**单播**回复ARP响应。
- **跨网段**：源主机**不能**直接ARP解析目的主机的MAC，而是解析**默认网关（路由器接口）**的MAC地址。

##### 跨网ARP过程
![[deepseek_html_20260911_acc363.html]]
PC1 访问跨网段 PC2 时，PC1 先判断目标不在本网段，决定把数据交给默认网关 192.168.1.1。  
PC1 发出的 ARP 广播问的是“谁是 192.168.1.1”，不是“谁是 10.0.0.20”。这个广播只在 192.168.1.0/24 内传播，PC2 收不到。  
路由器 G0/0 收到广播，发现目标 IP 是自己，直接单播回复自己的 MAC。PC1 缓存网关 MAC，然后把数据帧发给网关。  
路由器查路由表，发现 10.0.0.0/24 是直连，出接口 G0/1。但路由器不知道 PC2 的 MAC，于是从 G0/1 再发一次 ARP 广播问“谁是 10.0.0.20”。  
PC2 收到后单播回复自己的 MAC，路由器缓存，重新封装二层帧发给 PC2。  
所以 PC1 的 ARP 响应是网关直接给的，不需要经过 PC2；PC2 参与的是路由器发起的第二次 ARP。ARP 广播不能跨网段，因此不存在“路由器把 PC1 的请求转给 PC2 再带回来”这种情况。跨网段通信中，ARP 只在各自广播域内解析下一跳，IP 地址全程不变，MAC 地址逐跳替换。

# （七）移动IP
## 1.移动IP的概念
移动IP标准：代理发现，向归属代理注册，数据报的间接路由选择
移动IP的核心目标是：让移动节点（如手机、笔记本）在**改变网络接入点（跨越不同网段）时，无需改变其永久的IP地址**，从而保证正在进行的通信不中断。
要实现这一点，必须掌握以下几个核心角色和地址概念：
- **移动节点（MN）**：换了网线/Wi-Fi，更换了接入网络的设备。
- **归属网络与归属地址**：移动节点原本所在的网段，以及它原本拥有的、永久不变的IP地址（标识它是谁）。
- **外地网络与转交地址（COA）**：移动节点目前漫游到的网段。**转交地址**是移动节点在当前外地网络获得的一个临时IP地址，用于告诉别人“我现在在哪”。
- **归属代理（HA）**：位于归属网络的路由器，负责“拦截”发往移动节点的数据包。
- **外地代理（FA）**：位于外地网络的路由器，负责为移动节点提供路由服务（注：在IPv6中通常取消外地代理，由移动节点自己充当）。
## 2.移动IP通信过程

移动IP的通信分为三个阶段：代理发现与注册、数据包接收、数据包发送。

1.  **注册阶段（报到）**
    *   移动节点漫游到外地网络，通过外地代理（或DHCP）获取一个**转交地址（COA）**。
    *   移动节点向**归属代理（HA）**发送注册请求，告知HA自己的转交地址。
    *   归属代理记录下这个绑定关系（即：永久IP -> 当前转交地址）。
2.  **接收数据（隧道技术）**
    *   通信对端（CN）发给移动节点的数据包，目的地址依然是移动节点的**归属地址**，因此数据包会先到达**归属网络**。
    *   归属代理（HA）拦截到该数据包，发现移动节点已漫游，于是利用**IP隧道技术**（通常是IP-in-IP封装），把原始数据包整个作为数据，在外面套上一个新的IP首部（目的地址为转交地址），发给外地网络。
    *   外地代理（或移动节点自己）收到后，剥离外层IP首部，还原出原始数据包，交给移动节点。
3.  **发送数据（三角路由问题）**
    *   移动节点回复通信对端时，**不需要经过归属代理**。
    *   移动节点直接将数据包发给外地网络的路由器，由外地网络直接路由到通信对端。
    *   **三角路由（Triangle Routing）**：通信对端到移动节点的路径是“CN -> HA -> MN”，而移动节点到通信对端的路径是“MN -> CN”。去程和回程路径不一致，形成了一个三角形，这被称为“三角路由问题”（虽然增加了HA的负担和延迟，但为了保持IP不变，这是基础移动IP的代价）。
