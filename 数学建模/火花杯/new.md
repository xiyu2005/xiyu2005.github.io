
### 1. 问题建模与分析

这是一个在时变网络拓扑和时变链路容量下的多目标（低丢包、低时延）优化问题。其核心挑战在于：

1.  **双重动态性**：
    * **出口位置动态**：移动接收车的位置随时间变化，导致能够直接上传数据（S2GL）的传感器节点也在不断变化。
    * **出口带宽动态**：S2GL的链路带宽是随时间快速波动的周期函数，且每个传感器节点的相位不同，导致可用带宽难以预测和稳定利用。

2.  **资源竞争与拥塞**：
    * **Mesh内部拥塞**：大量数据流需要通过有限的Mesh网络链路（$B_{sensor}=10$ Mbps）涌向少数几个出口节点，极易在出口节点附近造成拥塞。
    * **S2GL带宽竞争**：在某一时刻，一个接收车覆盖范围内的6个传感器会竞争该车有限的总接收带宽（$B_{receive}=100$ Mbps）。
    * **无缓存约束**：传感器无法缓存数据的硬性要求，意味着在任何时刻，一个数据流的端到端路径必须全程带宽可用，否则就会产生丢包。这使得调度决策必须非常精确。

3.  **规模庞大**：
    * 网络规模为 $20 \times 30 = 600$ 个节点。
    * 数据流总数高达 1800 条。
    * 需要在 90 个时间步（每秒一次决策）内完成所有调度。

穷举所有可能的路径和速率分配方案是不现实的，因此必须设计高效的启发式或近似优化算法。

### 2. 数学模型关键要素

为了设计算法，我们首先将问题中的关键元素进行数学化定义。

* **集合定义**:
    * 传感器节点集合: $S = \{(x, y) | 1 \le x \le M, 1 \le y \le N\}$
    * 数据流集合: $F = \{f_1, f_2, \ldots, f_{1800}\}$
    * 移动接收车集合: $V = \{v_1, v_2, v_3\}$
    * 时间步集合: $T = \{0, 1, 2, \ldots, 89\}$

* **核心参数**:
    * 数据流 $f_i$ 的属性: 起始节点 $(x_i, y_i)$，起始时间 $t_{start, i}$，总数据量 $s_i = 10$ Mb，要求速率 $r_i = 5$ Mbps。
    * Mesh网络容量: $B_{sensor} = 10$ Mbps
    * Mesh网络时延: $t_{sensor} = 50$ ms
    * 接收车总带宽: $B_{receive} = 100$ Mbps

* **时变函数与状态变量**:
    * **车辆位置**: 接收车 $v_j$ 在时刻 $t$ 覆盖的传感器集合为 $C_j(t)$。
        * $x_{\text{pos}}(t) = \lfloor 1 + (M-3) \frac{t}{100} \rfloor = \lfloor 1 + 27 \cdot t/100 \rfloor$
        * $C_j(t) = \{(x,y) | x_{\text{pos}}(t) \le x \le x_{\text{pos}}(t)+2, y \in \text{Rows}_j\}$
    * **S2GL带宽**: 传感器 $(x,y)$ 到接收车的可用带宽为 $b_{x,y}(t)$。为保证仿真可复现，相位 $\phi_{x,y}$ 需确定性生成，例如与位置相关：$\phi_{x,y} = (x + 2y) \pmod{10}$。
        $$b_{x,y}(t) = B_{x,y}^{peak} \times \left(1 - \frac{|((t + \phi_{x,y}) \pmod{10}) - 5|}{5}\right)$$
    * **数据流状态**: 每个流 $f_i$ 需维护一个状态机：
        * `current_position`: $(x,y)$，流当前所在的物理节点。
        * `path`: `list`，当前规划的移动路径。
        * `transmission_timer`: `float`，当前跳的剩余传输时间（ms），初始为 50ms。
        * `remaining_data`: `float`，剩余需上传的数据量（Mb）。
    * **链路负载**: $L_{uv}(t)$，表示在 $t$ 时刻，Mesh链路 $(u,v)$ 上承载的总流量速率。

* **决策变量 (在每个时间步 $t$ 需要决定的)**:
    * 对于每个需要规划路径的流 $f_i$: **路径选择 $P_{i}(t)$**。
    * 对于每个已到达出口的流 $f_i$: **速率分配 $z_{i}(t)$**。

* **目标函数**:
    1.  **最小化丢包率**:
        $$\text{Minimize} \left( 1 - \frac{\sum_{i=1}^{F} (s_i - s_{rem, i, T})}{\sum_{i=1}^{F} s_i} \right)$$
    2.  **最小化平均传输时延**:
        $$\text{Minimize} \left( \frac{1}{F_{completed}} \sum_{i \in F_{completed}} (t_{end,i} - t_{start,i}) \right)$$

### 3. 求解思路与调度算法设计

采用基于时间步进的启发式算法。算法的核心是**精确跟踪每个数据流的物理传输进度**，并为处于空闲状态（即完成一跳传输后，等待下一步指令）的流进行动态路径规划和资源分配。

**算法步骤:**

1.  **初始化 (t=0)**:
    * 为每个传感器 $(x,y)$ 设定一个固定的相位 $\phi_{x,y} = (x + 2y) \pmod{10}$。
    * 生成初始的600条数据流。初始化每个流的状态：`current_position` 为其生成点，`path` 为空，`transmission_timer` 为 0，`remaining_data` 为 10 Mb。
    * 将所有数据流加入`active_flows`列表。

2.  **时间步进循环 (for t = 0 to 89)**:

    a. **系统状态更新**:
        * 计算3辆接收车在时刻 $t$ 的位置，确定当前的出口节点集合 $C(t) = \bigcup_j C_j(t)$。
        * 计算每个潜在出口节点的瞬时S2GL带宽 $b_{x,y}(t)$。
        * 重置所有Mesh链路和接收车的瞬时负载：$L_{uv}(t)=0$, $L_{v_j}(t)=0$。
        * 在 $t=30$ 和 $t=60$ 时，生成新流量并加入`active_flows`。

    b. **流传输进度处理 (核心)**:
        * 遍历所有`active_flows`，模拟在过去1秒内（1000ms）的移动：
            * 对每个流 $f_i$，`time_to_process = 1000`。
            * `while time_to_process > 0`:
                * 如果流 $f_i$ 的路径 `path` 为空，则跳出循环（等待路径规划）。
                * `time_needed = f_i.transmission_timer`。
                * 如果 `time_to_process >= time_needed`：
                    * 流完成当前跳的移动。更新`f_i.current_position`到路径的下一跳。
                    * `time_to_process -= time_needed`。
                    * 从`f_i.path`中移除已完成的一跳。
                    * 如果路径 `path` 变为空，重置 `f_i.transmission_timer = 0` 并跳出；否则，重置 `f_i.transmission_timer = 50`。
                * 否则（本秒时间不足以完成一跳）：
                    * `f_i.transmission_timer -= time_to_process`。
                    * `time_to_process = 0`。

    c. **路径规划与上传调度**:
        * **识别待调度流**: 找出所有处于“空闲”状态的流（`f_i.path` 为空）。
        * **优先级排序**: 对所有“空闲”流根据**紧迫性**进行降序排序。
            * **紧迫性指标**: 比较到达出口所需的最短时间和数据本身所需的传输时间。
                $$\text{Priority}(i) = \frac{\text{min\_dist}(i, C(t)) \cdot t_{\text{sensor}}}{s_{\text{rem},i} / r_i}$$
                其中 `min_dist` 是流当前位置到最近出口的曼哈顿距离。该值越大，意味着行程时间占总任务时间比例越高，越紧迫。
        * **逐一流进行决策**: 遍历排序后的“空闲”流列表：
            1.  **若流已在出口节点** (`f_i.current_position` in `C(t)`):
                * 此流优先上传数据。计算其可分配的瓶颈带宽：
                    $$B_{bottleneck} = \min(r_i, (b_{x_e,y_e}(t) - L_{S2GL, e}(t)), (B_{receive, j} - L_{v_j}(t)))$$
                * 分配速率 $z_i(t) = \min(B_{bottleneck}, f_i.remaining\_data)$。
                * 更新S2GL链路和接收车的负载 $L$。
                * 更新 `f_i.remaining_data -= z_i(t) * 1s`。若数据传完，则从`active_flows`移除并记录完成时间。
            2.  **若流不在出口节点**:
                * 为此流规划一条前往最佳出口的路径。
                * **路径成本**: 使用Dijkstra算法寻找成本最低的路径。链路 $(u,v)$ 的成本综合考虑跳数和拥塞：
                    $$\text{cost}(u,v) = 1 + \alpha \cdot \frac{L_{uv}(t)}{B_{sensor}}$$
                    $\alpha$ 是拥塞惩罚因子。
                * **分配带宽与路径**: 找到最优路径 $P^*$ 后，计算路径瓶颈带宽 $B_{mesh\_bottleneck}$。分配速率 $z_i(t) = \min(r_i, B_{mesh\_bottleneck})$。
                * **更新状态**: 将路径 $P^*$ 存入 `f_i.path`，设置 `f_i.transmission_timer = 50`，并更新路径上所有链路的负载 $L_{uv}(t)$。

3.  **模拟结束与评估**:
    * $t=90$ 循环结束后，所有`active_flows`中剩余的`remaining_data`计为丢包总量。
    * 根据所有完成流的起止时间，计算平均传输时延。

### 4. 可视化方案
* **流传输进度动画**: 动态展示在90秒内，代表数据流的粒子如何在网格中逐跳移动。粒子的颜色可以表示其状态（例如：移动中、等待规划、上传中）。
* **拥塞热力图**: 在特定时刻 $t$，用颜色深浅渲染Mesh链路的负载率，直观展示网络瓶颈。
* **单流轨迹追踪**: 选取一个典型的流（如起始位置很远），绘制其在整个生命周期中的完整移动轨迹和在每个出口节点的停留上传情况。
